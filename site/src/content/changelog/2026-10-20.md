## A level, plus a profile

The standard has three conformance levels that say how much of it a graph uses. Some fields need
more than any level asks for: a clinic's graph has rules about data and review that a hobby
project does not. v2.6 lets a field write those rules down once, as a **profile**: a named,
versioned set of extra rules that sits on top of exactly one level, keeps every rule of that
level, and relaxes none.

A graph declares both halves, for example *Starter, plus a profile*. A checker that knows the
profile checks both. One that does not still checks the level, and says the profile is
*unverified* rather than calling the graph broken. The standard keeps a list of named profiles
and who looks after each; listing a profile records that it exists, and certifies nothing. The
list is empty at this release.

## Checking a copy

A release can now carry a manifest of file hashes at its root, computed by a method the standard
writes out step by step. Anyone holding a copy can recompute it and compare. The same idea runs
through the new section on data models: keep one master, generate the other forms from it, and
pin each form to the master's hash, so a copy that drifts is caught by a check rather than by a
reader.

## The checkers catch up

Several tools described one thing and did another. The quality checker's documentation said ten
dimensions scored out of fifty; the checker scored out of three each. The text is fixed, and an
eleventh dimension asks the question that kept coming back: when a hand-kept list goes stale,
what notices? The lattice validator now reads its vocabularies from a pinned copy of the master
model, and the instance validator says plainly when that master is not on your machine to
compare against, instead of failing.

## What this site shows

The page that shows what your agent reads first vendors four files from the standard and
publishes their hashes. This release changes one of them and the version all four are pinned to,
so the page is rebuilt and redeployed with the release.
