## Inherited is not the same as decided

A new workspace copies a handful of decision records from the template. Until now each copy
arrived in the same state the template held it in — including one that had sat as *proposed*
since March. Nobody who forked the template had made that decision, so nobody could close it, and
a count of open decisions across many workspaces returned a number that was mostly echoes.

v8.12 does two things about that. The template ratifies its own decision at template level,
once, with the record saying so. And the fork step stamps every copied decision record as
inherited, with the version it rode in on — derived from the copied files, never typed. A
workspace that genuinely wants to re-open an inherited decision removes the stamp, and that act
shows up in its own history.

Nothing already on your disk is changed by this release. The stamp and the ratification apply to
what a *new* workspace receives; applying either to an existing one is a change to your files and
yours to make.

## The question that was already being asked

The setup interview has asked for a default license for months, and named the project-fork step
as the thing that would use the answer. The fork step never read it. The ask was there, the
consumer was named, and nothing connected them — which reads as covered to anyone checking
whether licensing is handled.

The fork step now reads that default first and only asks when it is missing, then writes the
answer into the project's manifest as a field. *Not yet* is a valid answer and is written down as
one, because an undecided license and a forgotten one must not look identical later.

## Two silent failures, and a third found on the way out

A template's front matter carried unquoted placeholders and did not parse. Two lines in the
ignore file carried a comment after the pattern, which that file format does not allow, so the
patterns matched nothing — a build-output folder was never ignored. The first report named one
line; the fix covers every placeholder in the file, because the line was an instance and the
class was the defect.

While checking this release, the conformance checker went red on a line that reads *"30→31
templates"* — a true statement from an earlier release, kept as history. The checker was reading
history as a present-tense claim. Editing the history to make the checker happy would have been
the wrong repair; the checker now skips comments, and a deliberately wrong count still fails it.

## What this site shows

The page that shows what your agent reads first vendors four files from the standard and
publishes their hashes. A release changes two of them and the version they are pinned to, so the
page is rebuilt and redeployed with the release rather than left describing the one before.
