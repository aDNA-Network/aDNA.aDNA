## What was actually inspected

[D] T0: ten targets × six canonical viewports × two requested themes = 120 captured PNGs. Reports and reproduction commands are under `how/campaigns/campaign_garnier/evidence/research/t0/`; full PNGs are local, ignored evidence. T0 writes a theme storage key and toggles a root CSS class, so it cannot establish native theme behavior on foreign sites. Its report records only the first requested theme.

[D] Native companion: twenty fresh contexts, each light preference and reduced motion, no DOM class/storage modification; forty committed PNGs. Each has a first screen and a subsequent frame after requesting a one-screen window scroll. All forty frames were visually inspected through labelled contact sheets. Nine sites returned content; Nous returned a checkpoint. The Stripe desktop second frame did not advance meaningfully, so deeper desktop layout is unverified there. Native captures do not establish default-theme choice, complete mobile operability, contrast compliance or normal-motion behavior. The requested scroll was recorded by the script, but actual scroll offsets were not recorded; the images bound the claim.

[D] Counts in per-site frontmatter were reconciled with rendered frames. Hero words include visible headline plus first synopsis, excluding actions, utilities, proof panels and metadata. OWID has no synopsis and its headline is H2. Linear's DOM duplicates its title; counted once visually. Section counts are **sampled nonutility H2 groups**, including subsections, excluding known cookie/outline/footer headings. They are not full-page visual section counts. Hidden/clipped navigation descendants were excluded manually. CTA count is the hero's direct action links, excluding search, account utilities and consent; a hero action need not be visible at the initial fold.

## Distributions, not prescribed targets

[D] Hero words: Stripe 9, OWID 11, Vercel 13; Linear/Hugging Face/Mastra 19; Ethereum 21, MCP 22; GOV.UK 38. Range 9–38: compact product/registry descriptions cluster around 19–22; a design-system explanation is longer. This heterogeneous sample does not define an optimal aDNA word count.

[D] Sampled H2 groups range 2–14: Vercel 2; Stripe 5; Linear/Hugging Face/Mastra 7; MCP/Ethereum 9; GOV.UK 10; OWID 14. Vercel's T0 reports 17 H2s versus two visible in the native pre-scroll DOM. Markup, hidden content and rendering state make these poor proxies for visual length; no new section budget is inferred.

[D] Primary navigation destinations range 4–6: Vercel 4; OWID/Ethereum 5; other usable sites 6. Hero actions range 0–2: MCP has no task CTA in its introduction; four sites have two. Ethereum's start action and GOV.UK's mobile start action are below the initial fold in these captures. Search and task lists matter more on research/docs surfaces than counting identical buttons.

[I] The recurring patterns are a clear reading hierarchy, concrete objects to inspect, and task-appropriate routes. They justify the proposed applications in [[garnier_quality_research]], together with the primary research cited there. They do not demonstrate conversion, trust, comprehension or performance improvements for aDNA.
