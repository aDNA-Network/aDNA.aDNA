# Idea: `pattern_graph_card.md` — the fleet-teachable graph-card pattern

`what/patterns/` holds 24 patterns and none for the fleet's most-repeated presentation unit: the **graph card**. The pieces exist and are ruled or building elsewhere — ADR-020 (Terminal, ratified: `graph_card` as shared atomic unit), `Home.aDNA/what/specs/spec_graph_front_page.md` (the content/data contract, v0.2.0 `proposed`, now five faces: web · TUI · Obsidian · Exchange · chat), WebForge's implemented `GraphCard.astro` four-band component, and the aDNA-site registry tier vocabulary. What is missing is the *pattern document* that teaches the ownership split (Home = content contract · WebForge = web visual law · Terminal = TUI binding · each persona = its own voice) and the invariant: **same four bands, same field sources, every face** — so a graph is recognizably one thing everywhere it appears.

**Proposal:** author `what/patterns/pattern_graph_card.md` citing the ruled owners (never re-authoring their contracts), and carry the fork-template hook: the Home spec's §5 genesis clause already demands `skill_project_fork` land tier-1 card fields at fork time — the pattern is where that demand becomes teachable. First chat-face exemplar shipped 2026-09-16 (ShareOMICS intro post). ⛔ Filing only; pattern authorship is Rosetta's act.
