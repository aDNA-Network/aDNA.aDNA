# Workload, uncertainty and phase commitments

[D] The original 26-mission, 26-session, 1,637 kT proposal is preserved in `proposal_20260914.tar.gz`. It used identical estimated/calibrated session values without a stated calibration basis. This amendment does not recast that arithmetic as measured execution performance.

[D] Revised frontmatters derive **38 missions / 47 estimated agent sittings / 2,444 kT content-load**. They include twelve concrete documentation tranches plus the bounded coordinator. Tier distribution: 34 opus, 4 sonnet, 0 fable. Tiers are judgment classes, not a claim that Codex has switched vendor models; executor_runtime remains codex. No enum extension.

[I] ADR-016 formula: transition allowance of 23 kT per estimated agent sitting plus explicitly bounded work. Tranche source-load proxies derive from actual bytes; review/verification allowances are judgment estimates. All calibration fields are null with calibration_status uncalibrated until a measured comparable basis is cited. The reporting script preserves nulls rather than turning missing calibration into zero. Use an initial ±50% planning uncertainty for work allowances; this is a contingency assumption, not a statistical confidence interval. Context-load includes reviewer work when performed; actual scorer usage must be accounted for separately and summed once. Human recruitment, panel scheduling and operator response delays are not agent sittings. Billing/cache costs are separately measured or unavailable, not inferred from this forecast.

## Progressive closure

Every mission appends its objectives, evidence links, findings, provider contributions and rough actuals to the rolling closure ledger when they arise. P6 validates the accumulated record and graduates knowledge; it does not repeat all earlier evidence collection. Estimate-vs-actual drift above 2× triggers the ADR-016 retrospective. A reduced estimate never permits an uninspected page or missing human result to be marked complete.
