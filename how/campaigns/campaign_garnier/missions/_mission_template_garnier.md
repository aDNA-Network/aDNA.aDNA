# GARNIER mission authoring template

[I] Use the complete root `template_campaign_mission.md` plus the additive frontmatter demonstrated by [[mission_garnier_p0_1_baseline]]. Required order: Read cold → Why → Where we are (dated evidence) → Scope → Objectives table → Constraints & gates → Goal/exit → Verification pair audit → Budget → Definition of done → Campaign context → Progress → Completion summary → five-line AAR.

Frontmatter requires identity, owner, campaign/phase, queued status, opus judgment class, additive executor_runtime, numeric kT budget and one estimated/calibrated session; dimensions, consumer patterns, patterns_to_author, dependencies/blocks, acceptance criteria, reached surfaces, controls and human gate. Each criterion needs a method capable of proving it, and every cross-pair states its limits. Reuse the existing schema and avoid placeholders in executable mission files. A missing provider pattern becomes a staged contribution; no local provider fork.
