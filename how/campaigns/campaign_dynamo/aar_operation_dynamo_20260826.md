## What the audit was right about, and what it was wrong about

Both are worth recording, because the audit's own accuracy is evidence about how much to trust the
next one.

- **F2 was slightly overstated.** It claimed the retired wrapper schema *"blocks
  `build_federation_edges.py` derivation."* Read at the object, the deriver resolves on
  `source_vault`, which was already declared — so edges would have derived. What it would actually
  have done is stamp the literal string `"genesis"` into 11 edges via its
  `pinned_at_commit`-or-`pin` fallback, **recording a non-commit as a commit**. Still a real defect,
  and arguably a worse one than a hard failure, because it is silent.
- **F3's file count was low.** It named 4 skills carrying unsubstituted template variables; counting
  found **5**. M04 carries the corrected list.
- **The mission's Act 1 instruction was internally inconsistent** and following it literally would
  have caused fresh drift: it directed a blanket `version_policy: commit_pin` while also directing
  that the Container exemplar be mirrored precisely — and that exemplar only uses `commit_pin` for
  `git` wrappers. A blanket application would have **de-pinned III from its live v0.6.0 release
  series**. Ruled per-kind at the plan gate.
- **The mission's Act 0 prediction was wrong.** It expected Venus's ADR-022 memo to bear on
  Hardware's machine-class enum. It is about the standard's `MEMBERSHIP_*` vocabulary having no term
  for a node below membership — Rosetta's surface, not Babbage's. The mission's own `else` branch
  applied; the memo's `ack_required: true`, which the mission never scheduled, was discharged and
  the substantive question filed rather than ruled from a corrections lane.

- **Worked** — Pre-recorded operator rulings let a successor session execute 9 acts without
  re-litigating a single decision. The Container exemplar made the wrapper migration mechanical.
- **Didn't** — Three memos and a registration were left owed by the original sitting, all four

  staging time. Verification of a migration means re-reading the *consumer* of the migrated field,
  not just grepping that the old key is gone.
