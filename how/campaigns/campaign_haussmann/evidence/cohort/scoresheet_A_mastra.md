## Anchor ambiguities

1. **D3 — the anchor conflates the primary metric with documentation hygiene (biggest calibration item).** Mastra likely has the fastest raw TTFS in the cohort (one command → Studio), yet strict anchor reading forces a 3 because two conjunctive hygiene clauses fail (prereqs not up front; no troubleshooting). For Archetype A, where D3 carries weight 18, the anchor as written lets hygiene subordinate the metric the archetype defines as "hard currency." Needs either a split (TTFS sub-score + hygiene sub-score) or an explicit rule for partial-clause satisfaction. Same ambiguity hits the MCP sheet from the other side (hygiene passes, TTFS unmeasured).
2. **D8/D9 — company-owned OSS compression.** The anchors assume community-governed projects; a healthy company-run framework with active venues, courses, hackathons and 27k stars scores 2/2, the same as a neglected repo. Under the A column the low weights (5+6) mostly absorb this, but calibration should state whether "governance" for Archetype A means corporate stewardship legibility (pricing, trust center, succession-by-company) rather than community governance artifacts.
3. **D10 — cumulative-tier anchors vs non-monotonic profiles.** The anchors are ladder-shaped ("as 3, plus… as 4, plus…"), but Mastra has 5-tier marquee items (official MCP docs server + skill, copy-as-context affordance) while missing 4-tier and even 3-tier basics (llms-full 404, .md twins unconfirmed, RSS unverified). Strict cumulative reading caps at 3; item-count judgment gives 4. I scored 4 and flag it — reviewer B may reasonably land 3. The instrument should state whether tiers are strictly cumulative.
4. **D6 anchor 4 — materiality of a single unsupported claim.** "Every claim verified or verifiable" read literally is broken by one marketing superlative ("the leading TypeScript agent framework") on an otherwise well-evidenced site. Needs a materiality rule (e.g., one non-quantitative superlative ≠ automatic drop to 3, but any unsupported *number* is).
5. **D7 — freshness vs staleness split across surfaces.** Activity signals conflict: recent blog posts and live star count vs a changelog dead since March. The "silent staleness" failure mode doesn't say how to weigh a stale changelog against otherwise-visible activity; I held D7 at 4 and logged the changelog under D4/D7 weaknesses.
