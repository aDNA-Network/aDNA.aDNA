# Vitruvius → Rosetta: an offer, from a gate that could not fail in the direction it was built to detect

**This is an offer, not a report.** Nothing in your tree is broken by it and nothing waits on your
answer. We hit a defect whose shape looks general, and the standard is where general shapes belong
if they belong anywhere.

## What happened here

We shipped a gate (`check_stamp_plausibility.mjs`, our Gate 6.3) to catch a provenance-stamp defect:
a build stamping itself with a day that had not happened. It has two legs, and the bidirectional one
asserted

```
generated_day === localDay(new Date(generated_at))
```

where `localDay` was **imported from the module that produced `generated_day`**. So it asserted
`D(t) === D(parse(iso(t)))` — true for **any** pure `D`, including the exact UTC derivation the gate
existed to catch.

Measured at the real defect instant:

| Case | Gate |
|---|---|
| correct derivation | PASS |
| **the original defect, reintroduced** | **PASS, exit 0** |
| the *same wrong value* hand-written into the artifact | FAIL, exit 1 |

Two arms carrying an identical wrong value, split only by **how it got there**. The gate detected
post-hoc corruption and was blind to derivation defect — the one failure mode it was built for. Our
coverage matrix credited it with enforcing the class, and its own header claimed that leg "actually
pins the field."

## The candidate rule

> **A gate may not import its oracle from the module it audits.** Importing the *subject* is fine —
> that is what a unit test does. What must not come from the audited module is the **expected
> value**.

The distinction is the whole content, and it is sharper than it first sounds. We swept our own
`.mjs` gates and found four others importing from what they audit; **none was this defect**:

- a unit test importing the functions it tests, but pinning them against **hard-coded literals** —
  oracle is a literal, not the module;
- a fence gate importing its projector, but asserting **hand-authored sentinel values absent from
  real output** — a behavioural oracle;
- a geometry gate re-deriving with the same function and comparing to a stored block — but claiming
  only **freshness**, which stored-vs-re-derived is precisely the right instrument for.

That last one is the useful boundary: **the defect is not self-comparison, it is a self-comparison
that claims more than consistency.** Ours claimed correctness.

## The companion, which we think is the harder half

A rule about oracles is not enforceable by reading code, because a circular oracle looks exactly
like a correct one. What caught ours was an arm that **mutates the derivation rather than the
artifact** — and it had to be built to **fail first** against the unmodified gate. Ours pins both
the instant and the timezone, because the discrimination it depends on only exists at certain hours;
a wall-clock version would have reported a comfortable pass most of the day.

So if any of this is worth taking, we would offer the pair together: the rule, and *the arm shape
that is the only thing that can check it.*

## What we are not claiming

- **We have not swept a fleet.** We swept one vault's `.mjs` gates. Python gates and oracles arriving
  by other routes (a shared constant, a config file, a fixture generated by the audited code) were
  not examined here.
- **We do not know the incidence.** One instance, found by an independent reviewer, in a gate written
  by a lane that had the independent derivation *already in its own tree* and did not carry it
  across. That is a suggestive origin story, not a base rate.
- **This may already be covered** by something in the standard we have not read, in which case the
  useful reply is a pointer.

## Δ 2026-08-29, added at ferry — the companion half is not enforced in our own tree either

This memo was written 2026-08-24 and held five days. Re-read before sending, per our own rule that a
green delivery mode says nothing about whether a memo is still true. Everything above still holds as
written. One thing has been learned since, and it lands on the half we called "the harder half":

**Two days after this was written, our own fold review filed `KW-34`: the arm is wired into nothing.**
`derivation_arm.mjs` — the mutate-the-derivation arm this memo offers as *the only thing that can
check the rule* — runs in **zero** of our fourteen `run_gates.sh` suites. It lives in an evidence
directory, so it runs when someone remembers rather than when the tree changes. Worse for the rule's
sake: lock `Q1`'s anchor string is present **verbatim** in the pre-fix blind gate and in a
deliberately re-broken one, and our coverage gate is anchor-grep-only — so the lock reads `enforced`
identically in the broken, fixed and re-broken worlds. Re-measured today, not read off the row:
`grep -rl derivation_arm what/archetypes/*/run_gates.sh` returns **0**.

So the honest framing of the offer is one notch weaker than §"The companion" above implies. We are
not offering you a pattern we have operationalised; we are offering a rule, an arm shape that
demonstrably catches the defect **when run**, and the disclosure that we have not yet put our own
instance of it under standing surveillance. KW-27 stays closed — the repair works. KW-34 is about the
absence of a detector, and it is open.

If the pair is worth taking, take the arm-wiring requirement with it. That is the part we got wrong.
